# Ver.1.0 試作27 実装メモ

## 今回の目的

取得済み鳥へごはんをあげる動線を正常化し、仲間関連画面の操作責務を整理した。鳥13種類、なかよし進化3段階、ニックネーム、おきにいり、キッチン、おでかけ、保存データの仕様は維持する。

## お世話不能の再現手順

試作26を無変更の状態でローカル起動し、390 x 844相当のブラウザで次を確認した。

1. ホーム、なかまのようす、なかまずかん、とりのおうちから取得済み鳥を選ぶ。
2. 鳥の詳細画面を探す。
3. 図鑑の「ごはんをあげる」からキッチンへ進む。
4. すでに完成済みの料理が別の鳥を保持している状態を作る。

試作26には鳥の詳細ルートがなく、ホームとなかまのようすは状態確認から鳥別操作へ進めなかった。図鑑カードにはニックネーム、おうち、ごはん、おきにいりの4操作が並び、とりのおうちの鳥タップは一時反応だけだった。図鑑から指定した鳥はUI上の先頭に並んでも、完成済み料理の `preselectedCompanionId` が別の鳥のまま残ることを再現した。

## 根本原因

- 鳥別操作の中心となる詳細画面が存在せず、入口ごとに異なる処理を直接呼んでいた。
- 選択鳥は `ui.kitchenPreselectedCompanionId`、料理中データ、画面ローカル変数へ分散していた。
- 明示された鳥IDでキッチンへ移動しても、完成済み料理に選択IDがある場合は上書きされなかった。
- 完成料理画面は各鳥カードに同じ「このこにあげる」ボタンを置き、選択状態と実行操作が分離されていなかった。
- なかよし進化の装飾は既に `pointer-events: none` であり、タップ阻害の原因ではなかった。
- おでかけ判定そのものは単一tripだったが、画面責務が分散して理由表示が不十分だった。

## 修正内容

`companion-detail` ルートを追加し、取得済み鳥のSVG、表示名、正式名称、なかよしレベル、進化段階、現在状態と操作グループを表示する。未取得または不正IDは詳細操作を出さず、図鑑へ安全に戻す。

## 選択中companionIdの管理方法

一時UI状態に `selectedCompanionId` を追加した。`setSelectedCompanionId()` は取得済みかつ正式speciesのレコードだけを受け付け、既存の `kitchenPreselectedCompanionId` と同時に更新する。`getSelectedCompanion()` は不正・未取得IDを解除する。

ニックネーム、正式表示名、favorite、進化stageは選択IDとして使わない。appDataやJSON形式には選択状態を追加せず、既存のuiState保存キー内だけで扱う。詳細へ入る前のルート、パラメータ、縦スクロール位置もuiStateへ保存し、戻る操作で復元する。

## 食事処理への接続

詳細の「ごはんを あげる」は `companionId` をキッチンへ渡す。キッチンは明示IDを取得済みレコードとして再検証し、途中・完成済み料理の古い `preselectedCompanionId` より優先する。

完成料理では鳥カードを選択操作に限定し、選択中を文字と `aria-pressed` で示す。食事実行は主ボタン1個から既存中央処理 `KA.kitchen.feedCompletedCooking(companionId)` を呼ぶ。

## 二重実行防止

主ボタン押下時に `mealFeedInProgress` を立て、ボタンをdisabledにして「じゅんびちゅう…」へ変更する。処理中の再押下は無視する。中央食事処理も完成料理を消費する既存仕様を維持するため、連打、再描画、再読み込みで `mealCount`、`lastFedAt`、`bondLevel` が二重更新されない。

## 食事後の再描画と進化演出

順序は次のとおり。

1. 中央食事処理を実行して保存
2. 食事結果ダイアログを表示
3. 「つづける」またはEscapeで対象鳥の詳細へ戻る
4. 閾値到達時だけ進化ダイアログを表示

食事結果と進化ダイアログは同時に重ねない。進化既読は既存の `lastSeenEvolutionStage` で管理し、2から3、4から5へ到達した時だけ一度表示する。

## 仲間関連画面の変更前の問題点

図鑑に4つの直接操作があり、ホームにもおうち・キッチンの重複導線があった。なかまのようすは鳥別の比較や詳細遷移がなく、おうちの鳥タップは画面遷移しなかった。キッチンの鳥カードは選択と実行が同じ操作で、どの鳥が現在選択されているか分かりにくかった。

## 各画面の新しい役割

- ホーム: 代表鳥の状態と、状態に応じた主操作1個を表示する。
- なかまのようす: 取得済み鳥の表示名、なかよし、進化段階、食事・おでかけ状態を比較し、カード全体から詳細へ進む。
- なかまずかん: 全13種類の取得状況と成長情報を確認し、取得済みカード全体から詳細へ進む。未取得鳥に操作は出さない。
- 鳥の詳細: ごはん、おでかけ、おうち、ニックネーム、おきにいりを意味別グループで提供する。
- とりのおうち: 鳥を眺め、タップした鳥の反応を記録して詳細へ進み、家具と模様替えを扱う。
- キッチン: 鳥選択、料理選択、調理、食事だけを扱う。
- なかまと おでかけ: 鳥選択、行き先選択、出発、帰宅、受取、履歴だけを扱う。

## 削除・統合した重複操作

図鑑カードのニックネーム、おうち、ごはん、おきにいりの直接ボタンを削除し、「このこの ようすをみる」へ統合した。ホームの重複した鳥カードを外し、ヒーローの主操作を1個にした。キッチンの鳥別実行ボタンは選択カードと共通主ボタンへ分離した。キッチンとおでかけには設定操作を置かない。

## 主要な画面遷移

- ホーム / なかまのようす / 図鑑 / おうち -> 鳥の詳細
- 鳥の詳細 -> 選択済みキッチン -> 食事結果 -> 鳥の詳細 -> 必要時のみ進化演出
- 鳥の詳細 -> 対象鳥を選択済みのおでかけ
- 鳥の詳細 -> 対象鳥へフォーカスしたとりのおうち
- 鳥の詳細 -> ニックネーム編集 / おきにいり変更

## おでかけ中の扱い

試作26のキッチンはおでかけ中の鳥を食事対象から除外していなかった。この既存仕様を維持し、対象 `companionId` のみを「おでかけちゅう」と判定して「おでかけちゅうでも ごはんを とどけられるよ」と表示する。帰宅済みは「かえってきたよ」と表示する。

## 氷の伝説鳥の名称変更

利用者向け名称を「こおりの でんせつどり」から「でんせつのこおりのとり」へ変更した。`companion_ice_legend_bird`、speciesId、SVG、`designVersion: 1`、fixed seed、`plannedSpeciesId`、取得状態と履歴は変更していない。stage 1の視覚定義は名称を除外したSHA-256で試作26と一致する。

## 互換性

- nickname: `getCompanionDisplayName()` を全画面で継続利用する。
- favorite: 内部 `isFavorite` とfavorite処理を変更しない。
- なかよし進化: 13種類 x 3段階、共通stage算出、装飾、既読情報、reduced-motionを維持する。
- JSON: appData構造を変更せず、試作26以前のcompanions、キッチン、おうち、おでかけ、作品、jobSettingsを維持する。
- 保存キー4種と `schemaVersion: 1` は変更しない。

## 不正データ対応

存在しないID、未取得鳥、文字列以外の選択値は選択解除する。料理中の選択IDが無効な場合は、有効な一時選択または未選択へ補正する。通常appDataは全削除せず、既存のsafeStartと起動復旧を維持する。

## accessibility

鳥カードはネイティブbuttonとしてEnter・Spaceで操作できる。操作ごとの `aria-label` に表示名と行き先を含め、選択中は `aria-pressed` と文字で示す。主要ボタンは48px以上、disabled理由は文章で表示する。画面遷移後は見出しへフォーカスし、詳細から戻る時は元の鳥カードとスクロール位置へ戻す。

## reduced-motion

既存の `prefers-reduced-motion` を維持し、進化装飾は `pointer-events: none` のままとする。動きを止めても選択、食事結果、進化段階を文字で理解できる。
