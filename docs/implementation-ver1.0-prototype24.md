# Ver.1.0 試作24 実装メモ

## 今回の目的

既存機能を増やさず、標準おしごと `job_cleanup` の表示と報酬、おきにいり表記、取得済み鳥のニックネームを改善した。保存キー4種と `schemaVersion: 1` は変更していない。

## job_cleanupの名称変更

`js/constants.js` の正式定義を「おかたづけBOXをからにする」へ変更した。`taskId: "job_cleanup"`、有効設定、並び順、日替わり選択、既存達成履歴は維持する。標準おしごとの画面表示と親モードは正式定義を参照するため、同じIDの別項目は作成されない。

## スター報酬変更

`job_cleanup.rewardStars` を2へ変更した。達成時は従来どおり `KA.tasks.completeTask()` から `KA.stars.earnTask()` と中央台帳処理へ渡す。使える星、集めた星、日次獲得数、スター台帳を1回の処理で更新する。他の標準おしごととオリジナルおしごとは1スターのまま。

親モードでは `job_cleanup` の2スターを固定表示とし、`KA.tasks.updateTask()` へ値が渡っても2を維持する。たまごへのおしごとボーナスは既存の `recordTaskBonusIfEligible()` を変更せず、1日最大5ポイントを維持する。

## 過去履歴へ遡及付与しない仕組み

保存済みの達成レコードにある `rewardStars` とスター台帳は再計算しない。試作24への移行で正式定義が2へ変わっても、既存達成へ差額を付与しない。同日達成済みなら既存の `isCompleted()` が再達成を拒否する。

親モードで過去の達成を訂正する場合は、現在の正式定義ではなく達成レコードに保存された `rewardStars` を訂正台帳へ渡す。旧1スター達成は1スター、新2スター達成は2スターを訂正する。

## おきにいり表記変更

ホーム、なかまずかん、とりのおうち、キッチン、おでかけ、確認用ページ、READMEの利用者向け表示を「おきにいり」へ統一した。内部の `favorite`、`isFavorite`、`favoriteCompanion()`、保存済みデータは変更していないため、データ移行は不要。

## ニックネームの保存場所

取得済みcompanionレコードへ任意の `nickname` 文字列を保存する方式を採用した。1 speciesにつき1つの取得済みレコードを使い、再孵化時も同じレコードの `hatchCount` と `bondLevel` を更新する既存構造に合うためである。

種族定義の正式名称、`companionId`、`speciesId`、`isFavorite`、`hatchCount`、`bondLevel`、`mealCount`、`lastFedAt` は変更しない。新規孵化レコードには空文字を補完し、既存レコードも `ensureCompanions()` で安全に正規化する。

## ニックネーム正規化

`normalizeCompanionNickname()` は文字列以外を未設定とし、制御文字と改行を除去して前後空白を削除する。保存済み・インポート済みの極端に長い値はUnicodeコードポイント単位で12文字へ正規化する。

設定API `setCompanionNickname()` は取得済み鳥だけを対象とし、空白のみと13文字以上をエラーにする。UIは `maxlength="12"`、文字数表示、`aria-live` のエラーを備える。HTMLタグ風文字列はHTMLとして実行せず、各画面でエスケープまたは `textContent` を使って表示する。

## 表示名共通関数

- `getCompanionSpeciesName(companion)`: 正式な種族名を返す
- `getCompanionDisplayName(companion)`: 有効なニックネームを優先し、未設定なら正式名を返す
- `setCompanionNickname(companionId, nickname)`: 取得済み鳥へ保存する
- `clearCompanionNickname(companionId)`: 未設定へ戻す

ホーム、なかまのようす、図鑑、とりのおうち、キッチン、おでかけ、帰宅、おみやげ、おでかけ履歴は共通関数を利用する。孵化直後は正式な種族名を表示する。

## ニックネーム設定UI

なかまずかんの取得済みカードへ「ニックネームを つける／かえる」を追加した。ダイアログには鳥SVG、正式な種族名、入力欄、文字数、保存、キャンセル、設定済み時の「もとの なまえに もどす」を表示する。

ダイアログを開くと入力へフォーカスし、キャンセルまたはEscapeで閉じる。キャンセル後は元のボタンへ、保存・削除後は再描画された同じ鳥のニックネームボタンへフォーカスを戻す。未取得鳥にはボタンを描画せず、APIも保存を拒否する。

## 正式名称との使い分け

図鑑と設定ダイアログはニックネームを主表示、正式な種族名を補助表示する。ホーム、おうち、キッチン、おでかけはニックネームを優先する。未設定、不明データでは正式名または「なかま」を安全に使用する。

おでかけ履歴は既存の `speciesId` から現在のcompanionを解決するため、ニックネーム変更後は過去履歴も現在の表示名になる。`tripId`、`rewardPlan`、`claimedAt`、報酬重複防止データは変更しない。

## データ移行とJSON互換

試作23以前のデータとJSONは `nickname` 未設定として読み込む。試作24のJSONはcompanionレコード内の `nickname` をそのまま含み、インポート時に同じ正規化を行う。`ensureDataShape()` を複数回実行してもニックネーム、取得状態、おきにいり、孵化回数、なかよしレベルを初期化しない。

配列、オブジェクト、数値、空白のみは未設定にする。改行と制御文字を除去し、長すぎる値だけを12文字へ安全に正規化する。不正な1項目のためにappData全体を削除しない。

## アクセシビリティと390px

入力へlabelと説明を関連付け、最大文字数、エラー、保存結果を文字で伝える。操作ボタンは48px以上を維持する。12文字の表示には `min-width: 0` と `overflow-wrap` を使用し、鳥SVGや主要ボタンを縮小しない。ダイアログは390px以下で1列の操作ボタンへ切り替える。既存のsafe-areaとreduced-motion設定は維持する。
